## 1. Product Context

**Product name:** Smart Resume Analyzer

**Domain description:** Analyze resumes to extract candidate skills and evaluate alignment with a target role using ATS-style scoring.

**Purpose:** Help users submit resumes and receive structured insights (skill extraction) and compatibility scoring against a target job description.

**Target users (roles):**
- Job seekers (submit resumes; review ATS-style feedback)
- Recruiters / hiring managers (upload/view resumes; compare against role requirements)
- Admin / operators (manage baseline settings for scoring and evaluation)

**Core entities (baseline list):**
- Resume (document + extracted text/metadata)
- Job Target / Job Description (text describing a role)
- Parsed Candidate Profile (extracted skills + structured attributes)
- ATS Score (numerical + breakdown)
- Feedback Report (explanations and improvement suggestions)

**Primary workflows (MVP):**
1. Resume upload/parsing → extracted candidate profile.
2. Job description input → ATS scoring + feedback.

## 3. MVP Scope Notes

### MVP includes
1. **Resume ingestion (client → backend)**
   - User uploads a resume (PDF/DOCX/text) or pastes extracted text.
   - Backend performs resume text extraction/parsing.
2. **Job description ingestion**
   - User provides job description text (paste/upload text).
3. **Skill extraction & canonicalization**
   - Extract candidate skills from resume.
   - Normalize skills into a simple canonical form for matching (e.g., case/whitespace normalization + synonym mapping when available).
4. **ATS-style scoring**
   - Compute an ATS score and provide a breakdown (e.g., Skill match, Relevance, Coverage).
5. **Actionable recommendations (LLM-powered)**
   - Identify **missing skills**.
   - Provide **concrete suggestions** to improve resume sections (e.g., summary bullets, skills section updates, experience alignment).
6. **Client-side persistence (localStorage)**
   - Persist the most recent analysis inputs/outputs for the current browser session.

### Explicit non-goals (for MVP)
- No user accounts / authentication.
- No database or multi-tenant storage.
- No background job queue; analysis is synchronous for MVP.
- No fully automated resume rewriting; only recommendations and draft bullet suggestions.

### Deterministic vs LLM-assisted (initial split)
- **Deterministic**: basic resume/job text normalization, keyword/regex extraction scaffolding, and deterministic score components.
- **LLM-assisted**: skill identification from noisy text (where deterministic extraction is insufficient), evidence selection, and natural-language recommendations.

## 5. Risks & Open Questions

- **Accuracy targets**
  - Open question: define acceptance thresholds (e.g., skill recall/precision or human-judged usefulness of recommendations).
  - Mitigation: include lightweight evaluation harness + human review samples.
- **Resume format variability**
  - Risk: PDFs/docx parse poorly; OCR may be needed.
  - Mitigation: MVP supports text extraction best-effort; fall back to user-pasted text.
- **LLM variability**
  - Risk: recommendations may change between runs.
  - Mitigation: deterministic prompt template + structured output schema + retries on schema validation failure.
- **ATS score interpretability**
  - Risk: users distrust opaque scoring.
  - Mitigation: score breakdown must cite which skills/phrases contributed.


## 6. Acceptance Evidence

### Skill extraction quality
- Given a curated set of resume/job pairs (MVP evaluation set), the system returns:
  - a non-empty candidate skill list
  - a missing-skills list aligned to the job description
- **Evidence metric (MVP)**: % of test pairs where at least 3/5 expected missing skills appear in the missing-skills output (human-reviewed).

### ATS scoring quality
- Score breakdown includes:
  - measurable components (e.g., Skill Match %) and
  - a clear explanation of what drove each component.
- **Evidence metric (MVP)**: human rating (1–5) of score usefulness ≥ 4 for majority of sample cases.

### LLM output reliability
- LLM responses must conform to a predefined JSON schema.
- **Evidence metric (MVP)**: schema-conformance rate ≥ 95% on sample runs (retries permitted).

### Parsing robustness
- If extraction fails, UI must present a recovery path (e.g., paste text).
- **Evidence metric (MVP)**: ≥ 95% of uploaded documents result in usable text for downstream scoring.
